# Artifact for: HILL: Efficient Low-Latency Implementations of Linear Layers via Heuristic Search

## 1. Abstract / Description
This artifact provides the optimized circuit implementations (datasets/results) for the linear layers discussed in our ToSC 2026 paper "HILL: Efficient Low-Latency Implementations of Linear Layers via Heuristic Search".

By providing these explicit circuit representations, we aim to make our low-latency implementations readily available for other researchers to use directly in their hardware/software designs, which fulfills the criteria for the Artifacts Available badge.

## 2. Directory Structure and Contents
All optimized circuit representations are located in the `results/` directory. The subdirectories correspond to the different matrices evaluated in the paper:
`results/AES/`: Contains the optimized implementation of the AES MixColumns matrix (Section 4.1). The circuit achieves 270.4 GEs at depth 3, as reported in Table 3.
`results/FSE_SKOP15_32_Hadamard/`: Contains the implementation of the 32×32 Hadamard matrix from SKOP15, with results reported in Table 3 (see row "[SKOP15] Hadamard").
`results/FSE_SKOP15_16_Hadamard/`: Contains the implementation of the 16×16 Hadamard matrix from SKOP15, also reported in Table 3.
`results/...`: Additional directories correspond to other matrices discussed in the paper (e.g., the 148 (Hamming weight) matrix, involutory MDS matrices, etc.). The naming convention follows the description in the corresponding tables.

## 3. Data Format
Inside each folder, the text files (e.g., `.txt`) describe the sequence of XOR operations required to implement the target matrix. 

The format is straightforward:
All nodes (inputs, intermediates, and outputs) are represented by the `t` prefix. 
`t0` through `t{n-1}` (where `n` is the matrix dimension) denote the input nodes. In the paper, these correspond to the input variables `x0, x1, ..., x{n-1}`.
`t{n}` and above denote intermediate nodes generated by XOR operations.
Output nodes are marked with `y[out_index]` on the same line (e.g., `y[24]` indicates that this node corresponds to the 24th output of the matrix).

Operations are denoted using the standard XOR operator `+`. A line may contain two or three operands, corresponding to XOR2 or XOR3 gates, respectively.

An example from the AES MixColumns circuit:
t[32] = t[2] + t[10]
t[33] = t[1] + t[25]
t[34] = t[18] + t[33]
t[35] = t[9] + t[25]
t[37] = t[10] + t[26] + t[35]
...
t[46] = t[44] + t[45]  y[24]

In this example, `t0`–`t31` are the 32 input bits, `t32`, `t33`, … are intermediate nodes, and `t46` is marked as output `y[24]`.

Each line defines one gate. The total number of lines equals the total number of XOR gates used. The circuit depth can be derived by tracing the longest chain of dependencies from inputs to outputs.

## 4. Verification of Paper Claims
Reviewers can fully verify our claims regarding the number of XOR gates and the circuit depth directly from these result files. 

1. XOR Gate Count: Counting the number of lines in a file gives the total XOR gates. For circuits that use both XOR2 and XOR3 gates, the exact numbers can be obtained by checking the number of operands per line. For instance, the AES MixColumns file contains 59 lines with two operands (XOR2) and 20 lines with three operands (XOR3), summing to 79 gates, which matches the reported area of 270.4 GE (59×3.0 + 20×4.67 = 270.4).

2. Circuit Depth (Latency): The depth can be verified by propagating a topological order. The provided equations are written in a dependency-respecting order, so the maximum number of cascaded operations from any input to any output is exactly the circuit depth. For instance, output y[24] is computed as t[46] = t[44] + t[45], where t[44] and t[45] are themselves results of layer-1 operations, resulting in a total depth of 3.
